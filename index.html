01 / THE PRINCIPLE

别神化 GitHub。
它只是放大器。
放大你的能力，也放大你的空话。

很多人把 GitHub 当“自动变现平台”，这是第一层误解。GitHub 更像一个公开的能力载体：别人能不能看懂你的项目、复现你的结果、信任你的方法，决定了后面有没有生意。

所以别问“发什么容易赚钱”。先问三个问题：谁在为这个问题付代价？我能不能更高效地解决？我拿什么证明自己不是在吹？

04 / THE PLAYBOOK

从 0 到第一单，
只做五个动作。

每一步都带验收标准。没有“多加群”“疯狂群发”“复制一个爆款仓库”这种低质量捷径。

01

先找愿意付代价的问题

别问“你会不会买”。去问对方现在怎么处理、浪费了多久、花过多少钱、最烦哪一步。

验收：1 张真实问题卡
02

做一个可复现的开源成果

Demo、教程、模板都行。关键不是“发出来”，而是陌生人能不能跟着你的 README 跑通。

验收：1 个能上手的仓库
03

只让真正需要的人看到它

围绕真实搜索词写标题，围绕真实问题写拆解。不是到处刷屏，而是进入正确场景。

验收：具体反馈、搜索与咨询证据
04

把付费交付定义清楚

免费内容负责建立信任，付费服务负责解决差异化问题。范围、边界、变更、验收必须写清楚。

验收：1 张可报价服务卡
05

算净收入，不算幻觉

别只看营收。工时、售后、税费、风险和返工都得算进去，不然只是自我感动。

验收：是否真实盈利，证据是什么
05 / RED TEAM REVIEW

对抗式审核。
把最容易自嗨的地方先打掉。

这部分是整套教程的灵魂。很多人不是不会做，而是太容易在错误指标里获得虚假满足。

01

你验证的是需求，还是验证了自己喜欢这个东西？

如果没有目标用户反复提起，也没有过去处理这个问题的成本记录，那大概率只是你的兴趣，不是市场。

02

你拿到的是流量，还是拿到了愿意沟通的人？

访问量可以证明“有人路过”，但不能证明“有人想买”。最少要追到有效询盘，才算往前一步。

03

你展示的是能力，还是只是在堆功能？

陌生人能复现、能理解、能看到效果，比你悄悄多写 2000 行代码更有价值。

04

你卖的是结果，还是卖模糊承诺？

客户不会为“我很努力”付钱，只会为明确交付、确定边界和可验收结果付钱。

05

你算的是营收，还是算了真正到手的钱？

如果没有扣掉人工、返工、运维、税费和售后，那个数字基本没什么意义。

06

你是在建立资产，还是在制造一次性内容垃圾？

真正值钱的项目，应该越做越容易沉淀信任和复用素材，而不是每次都从零开始。

HARD RULES

先过这 4 个门槛，再说“这个项目能赚钱”。

  • 有人确实有这个问题，而且问题带来成本。
  • 你的仓库能证明你不是纸上谈兵。
  • 有人愿意继续沟通，而不是只点个 Star。
  • 你能给出清晰可验收的付费交付。

10 / NO SHORTCUTS

五条红线，
避开比赚钱更大的坑。

短期噱头很容易做，长期可信度更难做，也更值钱。

01

不要买 Star、刷流量或抄仓库

假指标解决不了真实成交，侵权和虚假数据只会提前透支信任。

02

不要把 GitHub Pages 当交易或 SaaS 平台

Pages 适合展示、文档和内容分发。收费产品与交易链路应该独立合规部署。

03

不要假装所有人都能收 GitHub Sponsors

先确认地区、账户、身份、支付与税务资格，无法确认就别把它写成确定收益。

04

不要在公开 Issue 索取敏感信息

客户资料、密钥和商务合同都不该出现在公开仓库里。

05

不要拿假设营收冒充真实案例

访问、粉丝、Stars 和订单根本不是一回事。混着说，就是误导。
