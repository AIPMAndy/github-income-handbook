# 12 条 AI 提示词（严禁捏造结果）

> 使用规则：AI 只帮助组织信息。涉及收入、截图、合同、引用和客户案例必须人工验证。

## P01 痛点筛选
你是产品研究员。根据以下已收集的原始访谈，列出前5个高频问题。每项区分“原话事实、推断假设、待调查问题”。不要虚构访谈。访谈：〔粘贴已脱敏内容〕。

## P02 竞品对照
对比我提供的3个真实竞品资料，从目标用户、免费功能、收费边界、差异化、信息缺口分析。证据不足时明确写“未知”。资料：〔引用〕。

## P03 README 编辑
将下述项目事实改写为三分钟可复现的 GitHub README。必须包含：痛点、适合谁、安装与使用、真实演示、限制、授权、反馈入口。不能夸大性能。事实：〔粘贴〕。

## P04 商业模式反驳
用反方视角审查这个变现方案，找出5个可能让用户拒绝支付的理由，优先提供可验证实验，而不是口号。方案：〔粘贴〕。

## P05 交付边界
根据客户已确认的需求，给我一版可核验的交付清单、未包含范围、验收方式和变更流程。不能新增客户需求。需求：〔粘贴〕。

## P06 服务定价
帮我计算成本下限和不同工作量的报价范围，列出假设、风险准备金和需要补充的数据。禁止假装知道行业平均价格。数据：〔粘贴〕。

## P07 风险合规
审查本仓库 README、LICENSE、第三方素材、密钥、隐私信息与 GitHub Pages 商业使用边界。仅根据给定文本判断，并指出需要人工核验的政策链接。材料：〔粘贴〕。

## P08 内容选题
基于3条已证实的项目迭代记录，生成5个口语化的原创选题，每条必须说明引用的事实。资料：〔粘贴〕。

## P09 客户咨询分类
将脱敏客户反馈按功能请求、部署问题、定制需求、Bug、误用分类。每条列出下一步动作和证据，不得推断真实身份。文本：〔粘贴〕。

## P10 验收测试
根据交付清单生成正向/失败/边界场景测试点；每个测试点包括输入、预期、证据采集方式。交付清单：〔粘贴〕。

## P11 周复盘
仅基于我提供的访问、询盘、合同、回款、工时数据生成一页周报，区分数据事实和假设。不要以 Star 推断收入。数据：〔粘贴〕。

## P12 下一轮实验
根据访谈与拒绝原因，设计3个成本最小的实验。输出假设、预计成本、成功门槛、停止条件，且不保证收入。数据：〔粘贴〕。
