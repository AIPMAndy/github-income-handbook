# 实操手册 06：如何用自己项目讲真实变现故事

这里讨论作者的公开项目，仅使用已经明确披露的信息，不编造具体营收与订单。

## 案例 1：FreeToken——已有搜索进入的自述

GitHub：[AIPMAndy/FreeToken](https://github.com/AIPMAndy/FreeToken)

**事实层**：作者提到有从百度和 Bing 搜索进来的访客。搜索发现是值得分析的市场信号。  
**未知层**：具体访问量、访客目标、是否有付费咨询、咨询最终来源于哪个页面、付费转化路径。  
**实验**：在实际站点使用可归因的不同内容入口，记录用户主动咨询时提到的项目，结合收款记录做人工去重，不追踪无关个人数据。  
**否决条件**：搜索词代表“领免费资源”，但没有产生愿意支付交付成本的需求。

## 案例 2：GoodPaper——重复劳动的问题清晰，但未证实付费

GitHub：[AIPMAndy/GoodPaper](https://github.com/AIPMAndy/GoodPaper)

**事实层**：产品围绕论文格式检查、基础排版等重复劳动场景。  
**未知层**：学生、科研机构、出版机构、学校等谁拥有付费预算？软件与模板授权是什么？  
**实验**：访谈不同角色，各拿一份经授权的示例文档进行测试，量化真实节省时间和修改次数；不要虚构“平均节省 90%”。  
**潜在合规点**：处理论文草稿可能涉及未公开研究成果与个人数据，必须先确保授权与保护措施。

## 案例 3：HowToBeAnAICreator——公开教程可以形成个人信用

GitHub：[AIPMAndy/HowToBeAnAICreator](https://github.com/AIPMAndy/HowToBeAnAICreator)

**事实层**：作者已公开这个 AI 博主教程与在线网站。  
**未知层**：用户实际完成率、是否带来咨询订单、哪一章节驱动了主动联系。  
**实验**：在公开方法和模板中加入合理的“下一步”引导；把免费学习、付费个性化服务清楚分开，追踪来源时不违反平台导流政策。

## 严禁混淆的五类数据

- **Stars**：收藏/关注，不代表付钱。
- **Views / Visitors**：访问或去重访问，需声明指标口径。
- **粉丝数量**：跨平台受众，不代表 GitHub 收入。
- **商单数量**：可能来自账号业务，不能直接归因到开源项目。
- **回款**：只有与合同、收款和真实项目归因配对后，才能写成 GitHub 路径商业成果。

## 案例公开前审核问题

1. 有没有当事人许可公开信息？
2. 是否把自述写成第三方审计？
3. 有没有隐藏未履行合同或退款？
4. 是否把其他业务收入包装为本项目收入？
5. 是否说明了时间、样本和漏斗的不确定性？

**输出**：填好 [`case-evidence.md`](../templates/case-evidence.md)，再写内容。
