# 实操手册 07：先搞懂单位经济，再谈规模

## 一个示例（完全是假设）

假设本月有效访问 1,000 次，询盘率 2%，询盘成交率 10%，客单实收 1,000 元，额外现金/劳务总成本先填 800 元：

- 理论询盘：`1000 × 0.02 = 20`
- 理论订单期望值：`20 × 0.10 = 2`
- 假设回款：`2 × 1000 = 2000 元`
- 推演差额：`2000 - 800 = 1200 元`

这是数学演算，**不是你会拿到的结果**。需要明确：实际订单为整数，样本波动大；现金成本与总成本口径不同；税务、人工及返工可能继续降低净收益。

## 真正需要的经营数据

| 指标 | 定义 | 常见误区 |
| --- | --- | --- |
| 有效访问 | 具有需求的目标读者触达 | 所有点击都等于潜客 |
| 有效询盘 | 明确需求、时限、可付费场景 | 评论“支持”也算线索 |
| 报价 | 明确范围和验收的正式报价 | 发了一张价目表就算报价 |
| 订单 | 双方确认的付费协议 | 口头说“回头找你” |
| 回款 | 实际收到的钱 | 计划金额当现金流 |
| 净收益 | 扣除全部适用成本后的结果 | 营收当利润 |

## 记录办法

1. 每周用 [`metrics.csv`](../templates/metrics.csv) 保存一致口径的数值。
2. GitHub Insights → Traffic 提供滚动 14 天访问，不要盲目加总得到去重月访问。
3. 同步保留客户明确提及来源、合同与脱敏收款记录。
4. 对每个项目计算回款 / 工时 / 返工 / 售后。
5. 若你有多个渠道，不要把所有成交都记到 GitHub 头上。

## 三种可检验的停止规则

- **需求不成立**：多次真实访谈均找不到具体重复成本，回到选题。
- **获客不成立**：项目可用但目标用户不曾发现，改搜索问题与传播渠道。
- **经济性不成立**：单量增加但交付亏损，缩减定制或提高交付标准化水平。

相比“不断开新项目”，优先把有搜索信号的老项目变成可复用的商业化实验。
