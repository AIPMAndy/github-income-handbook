# 实操手册 01：零基础建一个能被人用的 GitHub 仓库

**目标：** 一位陌生人打开你的公开仓库，三分钟内知道它做什么，能按照说明开始尝试。

## 第 0 步：想好你要解决谁的问题

先用一句话写出来：**我帮 `[某个群体]` 解决 `[具体困难]`，通过 `[工具/步骤/材料]` 让他得到 `[可验收结果]`。** 比如“帮毕业生在 10 分钟内检查简历的基础排版”，比“全网最强 AI 赋能求职框架”清楚得多。

## 第 1 步：建立账号、开启安全保护

1. 打开 [github.com](https://github.com/) 并按提示注册账号；邮箱以你长期持有的工作邮箱为宜。
2. 进入个人头像菜单 → **Settings** → **Password and authentication**，按 GitHub 当前界面完成两步验证（2FA）。
3. 公开资料填写真实可公开的信息。头像、简介、网站与项目方向保持一致。切勿向任何人发送二步验证恢复码。

## 第 2 步：创建仓库

1. 点击网页右上角 `+` → **New repository**。
2. **Repository name**：用短、容易输入、能描述用途的英文名，例如 `resume-checker-guide`。
3. **Description**：一句话讲清用途，不要写空洞营销口号。
4. **Visibility** 选择 **Public**；若尚未取得第三方内容的公开授权，则先放私有仓库。
5. 勾选 README，选择合适的 `.gitignore` 和 LICENSE。没有授权许可的公开项目不自动等于人人可商用。
6. 点击 **Create repository**。

## 第 3 步：上传文件

- **网页端**：进入仓库 → Add file → Upload files，拖入本地文件并提交。
- **命令行端（会 Git 的读者）**：

```bash
git clone https://github.com/你的用户名/你的仓库.git
cd 你的仓库
# 将你原创且有权发布的文件复制到仓库目录
git add .
git commit -m "docs: publish first working demo"
git push origin main
```

不要把任何 `.env`、客户合同、收费订单、账户信息、数据库备份或 API Key 提交进去。

## 第 4 步：README 只回答六个问题

1. **给谁用？** 例如“非技术人员也可以运行”。
2. **能得到什么？** 必须可验证；不要写空泛愿景。
3. **如何开始？** 一步一步，包含前置条件。
4. **运行成功是什么样？** 给真实结果或脱敏截图。
5. **哪里可能失败？** 环境、依赖、版本和限制。
6. **如何反馈？** Issue 和外部业务官网分开。

可以复制 [`templates/README-PROJECT-TEMPLATE.md`](../templates/README-PROJECT-TEMPLATE.md) 再改成自己的实际项目。

## 第 5 步：完善门面

进入仓库首页右侧 **About** → 设置简短描述、项目网址（如果已上线）、Topics（必须和内容相关）；如有真实可用图片，可添加 Social Preview。不要用虚假数据做社交预览。

## 第 6 步：邀请陌生人复现

找一个没有参与开发的朋友，发送仓库链接，**别解释**。请他录下在哪一步看不懂、点错或失败。能跟着 README 完成成果后再推广。

## 最终验收

- [ ] 一个公开仓库可以访问
- [ ] README 三分钟能看懂
- [ ] 真实 Demo 可复现
- [ ] 许可证、隐私与依赖已核对
- [ ] 至少一个非作者成功走通

不满足这些条件，先修产品，别讨论“赚多少钱”。
