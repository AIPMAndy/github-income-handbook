# 对抗式审核（Red Team Review）

本项目最重要的升级，不是多写了几章，而是把最容易自嗨、最容易吹过头、最容易误导别人的部分先拆掉。

## 一、六个必须先问的问题

1. **你验证的是需求，还是自己的兴趣？**  
   如果没有真实用户反复提起，也没有历史成本，那大概率只是个人喜好。

2. **你拿到的是流量，还是愿意继续沟通的人？**  
   访问量只能证明“有人路过”，不能证明“有人想买”。

3. **你展示的是能力，还是只是在堆功能？**  
   仓库的价值，不在于代码多，而在于外人能不能理解并跑通。

4. **你卖的是结果，还是模糊承诺？**  
   客户不会为“我很努力”付钱，只会为可交付、可验收的结果付钱。

5. **你算的是营收，还是算了真正到手的钱？**  
   不扣工时、返工、售后、运维、税费，几乎所有“赚钱案例”都可能虚高。

6. **你是在建立资产，还是制造一次性内容垃圾？**  
   能沉淀信任和复用素材的项目，才值得长期投入。

## 二、四个门槛

如果下面四个条件一个都没过，就别急着说“这个项目能赚钱”：

- 有人确实有这个问题，而且问题带来成本；
- 仓库能证明你有解决能力；
- 有人愿意进一步沟通，而不是只点 Star；
- 你能给出明确的付费交付和验收标准。

## 三、最常见的自嗨信号

- 反复谈 Star、Fork、访问量，但没有一个真实询盘；
- 不停加功能，却没人能按 README 跑通；
- 一边说“开源变现”，一边没有任何付费交付定义；
- 把搜索流量、粉丝量、商单、GitHub 收入混为一谈；
- 只看营收，不看净收入。

## 四、结论

真正有价值的 GitHub 项目，不是“看起来像赚钱”，而是经得住这套红队问题。
